# Backend Feature Spec 24 — AI Reports & Export Surface [own-stack]

**Status:** PLANNED — the data/artifact half of the AI superpowers wave (research: `research/ai-features-research.md` §2). The `Reports` table and `Report` entity already exist (migration `20260907195152_AddOtpAndReports`); this spec plans the surface on top and contracts a fifth OBO scope.

## Goal

Give Griot a first-class, RBAC-scoped **reports + exports** surface so the AI report agents (ai 07), the web Reports & Audit Center (web 11) and the MCP report/audit tools (mcp 06) all read and persist through one governed door. Human members and AI OBO callers create, list, download and delete workspace reports; PDF/CSV artifacts are generated by ai 07 and stored through blob storage (spec 11).

## Existing schema (implemented)

`Reports(id, workspaceId, type, generatedBy, contentJson, generatedAt, promptContext?)` — `Report` entity, `Workspace 1:N` FK cascade (`backend/src/Griot.Domain/Entities/Report.cs`).

**Planned schema additions (migration `AddReportArtifacts`, in this spec's implementation branch):** `Title nvarchar(200)` · `Format nvarchar(10)` (`pdf` / `csv` / `json`) · `ArtifactUrl nvarchar(500)?` (blob ref via spec 11) · `DeletedAt datetime2?` (soft delete). No new tables.

## Scope model — the fifth OBO scope (PLANNED contract evolution)

- Today the `ai-on-behalf-of` principal carries exactly 4 scopes (spec 09, `docs/api/ai-service-token-contract.md`).
- This wave plans a **5th scope `CreateReport`** — a new, narrow, auditable capability, NOT a loosening of the existing grant (research §3.3.3 explicitly allows adding a scoped, auditable tool). It is used ONLY by report/audit tools (ai 07, mcp 06). All other boundaries stay: no deletes/invites/member management, and the auth/OTP surface (spec 23) is 403 for AI, forever.
- Until backend 24 ships, report-row creation uses the human-approved path (propose-before-write; web 10/11 executes as the user).

## Routes (PLANNED)

| Method | Route | Purpose | Role gate |
|---|---|---|---|
| GET | `/api/workspaces/{id}/reports?type=&format=&page=&pageSize=` | list report metadata (spec 18 pagination contract) | workspace member |
| POST | `/api/workspaces/{id}/reports` | create `Report` row + artifact metadata — body `{title, type, format, promptContext?, artifactUrl?}` | member; OBO needs `CreateReport` |
| GET | `/api/workspaces/{id}/reports/{reportId}` | report detail incl. artifact metadata | workspace member |
| DELETE | `/api/workspaces/{id}/reports/{reportId}` | soft-delete (+ blob artifact via spec 11) | Owner/Admin |
| GET | `/api/workspaces/{id}/reports/{reportId}/download?format=pdf\|csv` | stream artifact (spec 11); `Content-Disposition: attachment; filename="..."` | workspace member |
| GET | `/api/workspaces/{id}/audit-summary?window=24h&severity=` | pre-aggregated Audit/Error log rollup (spec 20 tables) — feeds the ai 06 auditor | Owner |

Report `Type` enum: `sprint_digest` · `task_summary` · `velocity` · `workload` · `ai_action_summary` · `custom`. (ERD remains the single source for enum names — extend via contract-sync when plotted.)

## AI report lifecycle (ai 07 ↔ 24)

1. User asks the Copilot (or schedules) a report → ai 07 fetches data through the existing REST/GraphQL surface (OBO scope reads) → deterministic aggregation in Node (numbers never come from the LLM) → CSV (RFC 4180) always + PDF (A4, brand tokens, accessible text layer) when requested → artifact uploaded to blob (spec 11, server-to-server) → `POST /api/workspaces/{id}/reports` (OBO `CreateReport` once shipped; propose-before-write before that) → `GET .../download` deep link + notification (spec 22) to the requester.

## Dependencies

- Spec 07/09 (auth; OBO) · spec 11 (blob artifacts) · spec 16 (workspace RBAC + dashboard reads) · spec 18 (pagination) · spec 20 (audit on every report action: `Report.Create/Download/Delete`) · spec 22 (notify on completion) · ai 07 · web 11 · mcp 06.

## Separation of Concerns

Controllers + download stream: `Griot.Api` · report orchestration + RBAC: `Griot.Application` · EF persistence + blob (spec 11): `Griot.Infrastructure` · entity growth: `Griot.Domain`.

## Docker & Deploy

No new containers. Artifact storage reuses the blob service from spec 11 (`CLOUDINARY_URL` or platform blob store); signed download URLs follow spec 11's contract.

## Acceptance Criteria (all PENDING)

- [ ] Download streams the correct format with `Content-Disposition`; missing artifact → 404
